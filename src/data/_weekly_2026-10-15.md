## TL;DR
- 本週三篇推理/執行期工作各指一個具體成本，問題並不相同：Barrier-Constrained Guidance 針對非同步執行下「已提交動作流」與新預測塊的邊界錯位（現有 delay-aware 方案需重訓/改架構/膨脹計算）；Verify, Act, Distill 針對測試時計算的增益每次執行都要重算；Flow-Support-Weighted Proposals 針對微調後流匹配解碼器集中、候選樣本塌縮。三者唯一共同點是把修復點放在推理/執行期，資料不足以支撐「研究重心已轉移」這類整體判斷。
- DEFT-VLA（力覺、接觸豐富）與 PRISM（精度、亞毫米精密操作）分屬不同軸，不宜併稱：前者處理階段依賴的視覺/本體與力覺信號衝突，後者把失敗歸因於流匹配目標對關鍵 flow time 監督不足。兩者在本資料中都只有截斷摘要，無基準與量化結果，增益無法在此核實。
- 社群側：資料顯示多個個別 GitHub issue 橫跨 lerobot（#1316 56 則、#1369 28、#2354 15）、gr00t（#136 27）、openpi（#687 18）觸及 LIBERO/MetaWorld 評測與復現；但這是個別使用者回報，不足以證明領域級無法復現。另注意 GitHub 快照日期為 2026-10-02，落在本報告窗口（10-08~10-15）之前，不能當作「本週」數據。

## Spotlight
### [DEFT-VLA: Stage-Localized Force Specialization for Contact-Rich Robotic Manipulation](https://arxiv.org/abs/2610.14854)
面向接觸豐富（contact-rich）操作：指出存在階段依賴的感官衝突——接近階段視覺與本體感受負責定位、力覺大致無用且可能干擾；接觸後力覺轉為關鍵，而無關視覺細節與相關機器人狀態可能成為 shortcut。方法為 DEFT-VLA（Dual-Expert Force-specialized Training）。提供摘要於「which retains the t…」處被截斷，共享主幹與階段專家的具體設計、階段如何界定，資料中皆缺失。

貢獻方向：把「力覺何時有效」由隱式學習改為顯式的階段結構先驗——按階段局部化力覺專精，而非全域 early-fusion。侷限與未證事項：(1) 摘要截斷，「保留共享主幹」與階段劃分/偵測機制在資料中不完整 > TODO: 需查證；(2) 資料不含任何結果、基準或延遲/參數量，因此「階段化是否真換來增益」與「雙專家是否抬高部署成本」皆無法核實 > TODO: 需查證。社群資料另有消費級 GPU 硬體摩擦（快照 2026-10-02：gpu_consumer×lerobot 2 條 issue 全未解決、gpu_consumer×isaaclab 2 條中 50% 未解決），但那與本方法無證據關聯，不可據此推論其上板成本。

> 把「力覺分階段有效」做成可複用的結構先驗，方向具體、對準觸覺 VLA 核心；但本資料不含結果，先別當已驗證的增益。

### [PRISM: Precision Forcing for Generalist Vision-Language-Action Policies](https://arxiv.org/abs/2610.14704)
針對主流範式（預訓練 VLM + 擴散/流匹配動作專家）在精密操作（如亞毫米級線纜插接）上不可靠，作者歸因於訓練目標在所有上下文與 flow time 上平均誤差、對少數決定成敗的 flow time 監督不足；提出 Precision Forcing 重分配監督。方法敘述同樣在摘要中被截斷。

診斷具體：把失敗定位到目標函數的監督分配，且屬對既有範式的訓練目標修補而非換架構——若成立，落地成本低、可疊加於現有 flow-matching VLA。侷限：(1) 資料無 PRISM 的基準、指標或任何對照數字，宣稱的精度增益在此無從核實 > TODO: 需查證；(2) 把監督往關鍵 flow time 傾斜是否損害非精密任務（取捨），資料未見討論 > TODO: 需查證。

> 把精密操作失敗歸因到 flow-matching 的監督分配，指向清楚；但在缺基準與結果前，增益與副作用都待驗。
